# Upgrading an existing ROCK BASE installation

This guide is for an existing installation with saved accounts and encrypted social sessions. It is not a first-install guide.

## Recovery set

Saved sessions require all of the following together:

1. the persistent SQLite database in `backend-db`
2. the exact existing `ENCRYPTION_KEY` in `backend/.env`
3. `backend-uploads` backup if uploaded media recovery matters

Current sessions are encrypted cookies in `SocialAccount.cookies`, not full browser profiles.

**Database backup plus the correct `ENCRYPTION_KEY` are both required to recover encrypted saved sessions.**

## Never run during a normal upgrade

```bash
docker compose down -v
docker volume prune
prisma migrate reset
prisma db push
```

Never replace or rotate `ENCRYPTION_KEY` on an existing installation.

## Safe upgrade flow

1. Fetch and review the approved branch or release.
2. Run the non-destructive preflight:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\preflight-upgrade.ps1
```

3. Create a verified database backup before rebuild:

```powershell
docker compose exec backend node dist/scripts/backup-now.js
```

4. Copy the verified database backup off-machine. Back up `backend/.env` securely and copy uploads separately when media recovery matters.
5. Preserve `backend/.env` and all existing named volumes.
6. Update code without changing data identity:

```bash
git fetch origin
git checkout <approved-commit-or-tag>
docker compose up -d --build
```

7. Wait for readiness:

```powershell
Invoke-WebRequest http://localhost:3010/readyz
```

8. Verify account count, then test one non-critical saved session in Farm View / Session Control before resuming campaign work.

## What survives a normal rebuild

`docker compose up -d --build` preserves named volumes when they are not deleted:

- `backend-db`
- `backend-uploads`
- `backend-backups`
- `backend-logs`
- `redis-data`

## Destructive reset

`docker compose down -v` deletes local persistent RockBase data. It is only appropriate for an explicitly approved disposable development reset, never a normal upgrade or recovery action.

See [PRODUCTION_DATA_CONTRACT.md](PRODUCTION_DATA_CONTRACT.md) for full persistence details.

## First login note

Existing user accounts remain unchanged during upgrade. Fresh installs use the one-time bootstrap configuration generated by `setup-rockbase.ps1`; it only creates an administrator when the database has no users.

## Rehearsal requirement

Before upgrading an installation with important account sessions, rehearse backup and restore-to-new-target in staging. This repository change is not a production deployment approval.
